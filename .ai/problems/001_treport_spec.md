## 1. Problem statement

Reporting requires (1) refreshing source Excel data files that contain Power Query and/or pivot-table data and (2) producing periodical Excel report workbooks by extracting filtered pivot results with required formatting. This is performed by a macro in `treport.xlsm` driven by configuration tables on the `settings` sheet.

**Revision context (2026-11-16, rev. 7):** placeholder model changed — `report_sheet` uses placeholders of the form **`max_<PivotTable field name>`** (e.g. `max_Week of Year`, `max_Year`). Each is resolved from the **maximum value** of that named PivotTable field in the relevant pivot context for the processed `data_files` row. Placeholder resolution is **not dependent on `data_files.filters`** (it is tied to the specified field in the pivot/data context used for that row). This replaces the prior rev.5/6 assumption that only fixed placeholders `max_weeknum/max_monthnum/max_year` are derived from `filters`/data-file filter resolution chains in that legacy form. `data_files.filters` remain a separate mechanism (generic per current decisions in related materials), not the source of these `max_<field>` placeholder values.
- **Revision context (2026-11-14):** filter logic/config baseline context (rev. 2 summaries). `general`: removed `report_week`/`report_year`; `category_delimeter` renamed to `delimeter`. `reports`: `articleLevel4Name_clean`, `targetAudience`, `name`. `data_files`: `filters` column (DSL). Older notes about fixed `max_weeknum/max_monthnum/max_year` derived from filter chains are **superseded** by rev. 7 (placeholders are `max_<PivotTable field name>` in `report_sheet`, resolved from that named field’s maximum, independent of `data_files.filters`).
- Rev. 5 (2026-11-14): Windows 10+/Excel 2021+ target context, no golden workbook, `group_rows` deferred, `run` requires `Refresh_data`/`Create_report` buttons bound to same-named VBA procedures (remove legacy `RunXlconcat`), `Trim` for configured strings in matching/substitution/naming/sanitization/collision checks (spaces inside preserved), evidence-driven handling notes for year/grouped fields where applicable, auxiliary tools allowed, final solution VBA-only, local Excel/gitignored workflow.
- **Rev. 6 (2026-11-15):** PivotTable available-fields principle for filter field availability/placement (P01); one-step auxiliary VBA build/import automation (FR-DEP).
- **Rev. 7 (2026-11-16):** placeholders in `report_sheet` are `max_<PivotTable field name>` (e.g. `max_Year`, `max_Week of Year`) resolved from that named field’s maximum in the relevant pivot/context for the processed `data_files` row; **not** derived from `data_files.filters`.

## 2. Goals and non-goals

### 2.1 Business goals
- Enable repeatable, configuration-driven `Refresh_data` and `Create_report` in Excel using VBA only (with auxiliary dev/deploy tools allowed off-runtime).
- Reduce manual work/errors; deterministic outputs for the same resolved inputs/config and data state.
- Ensure `data_files.filters` are applied generically by PivotTable available fields/values per current decisions (see related plan/specs); preserve layout rules per D7.
- Provide clear fail-fast diagnostics for missing/invalid config, data, pivots, fields, filters, or unresolved placeholders (subject to explicit exceptions defined elsewhere).
- Enable one-step auxiliary VBA build/import deployment preserving modular source architecture (FR-DEP).

### 2.2 Non-goals (out of scope)
- Designing or changing system/software architecture beyond the agreed Excel-macro solution in `treport.xlsm`.
- Implementing VBA/code, refactoring, or modifying repository files/data as part of this analysis.
- Requiring Python, PowerShell, BAT, or any other external runtime/tool for the end user to run the final `Refresh_data`/`Create_report` solution in Excel (auxiliary development/inspection/testing and deployment/build automation tools are allowed, but must not become runtime dependencies).
- Redesigning the VBA module architecture or physically merging modular source files into one giant `.bas` module as a substitute for proper build/import automation (P01).
- Producing or requiring a golden expected-output workbook as a mandatory acceptance prerequisite; validation is performed against functional requirements and actual source data (D18).
- Defining BI/business meaning of metrics/categories/TA/field semantics beyond names and filter expressions present in configuration and data.
- Implementing `group_rows` color-band grouping behavior in the current development scope (deferred to a separate task; D13).

## 4. Scope

### 4.1 In scope
1. **Configuration reading & validation** from `treport.xlsm` `settings` ListObjects `general`, `reports`, `data_files`, `placeholders` per revised schema and confirmed rules.
2. **`Refresh_data`**: locate configured data files in `input_path`, refresh Power Query/pivot data as required, persist refreshed data, and report outcome.
3. **`Create_report`**: per `data_files` row (in order), open source, resolve `filters`/`min`/`max` and placeholders deterministically, apply `data_files.filters` (data-file level) then per-`reports` filters (`articleLevel4Name_clean`, `targetAudience`) with confirmed placement/staging and PivotTable field-availability rules; generate output workbooks/sheets per `reports` and `data_files` order with required copy/format/naming; save outputs and report outcome.
4. **Deterministic rules** for file resolution, `filters` grammar/interpretation, `min`/`max` resolution, multi-value matching via `general.delimeter`, pivot field availability/placement (P01), copy range, placeholder substitution/naming, idempotent overwrite, and fail-fast error behavior.
5. **Operational/user-visible outcomes**: clear success/failure messaging sufficient to identify failing operation, config row/name, file path, sheet, field, filter/expression, or value.
6. **Deployment/build automation (auxiliary, non-runtime):** a one-step build/import process or equivalent consolidated deployment artifact that assembles all current modular VBA sources/document-module code into a working copy of `treport.xlsm` without manual multi-module import, while preserving modular source architecture and leaving the final workbook VBA-only at runtime (FR-DEP).

### 4.2 Out of scope
- Any non-Excel runtime, scheduler/orchestrator, UI redesign, or changes to source data content/pipelines.
- Requiring Python, PowerShell, BAT, or any other external runtime/tool for end-user execution of the final VBA solution (auxiliary development/inspection/testing and deployment/build automation tools are allowed and not in scope as runtime dependencies).
- Recovery/merge of concurrent edits or multi-user locking workflows beyond deterministic failure on locked/unavailable resources.
- Historical-data correction, metric definition changes, or new report types not representable by existing config model.
- Defining BI/business meaning of metrics/categories/TA/field semantics beyond configured names and filter expressions.
- `group_rows` color-band grouping behavior (deferred to a separate task; not in current development scope, D13).
- Physically merging all VBA source into one giant `.bas` file as an architecture change, or any deployment approach that damages module identities/references/document components.

## 5. Constraints

- **Artifact/architecture:** Solution operates within the existing `treport.xlsm` Excel-macro model and configured `settings`/`run` ListObjects. Modular VBA source architecture must be preserved (P01).
- **Implementation/runtime constraint (project, rev. 5; clarified rev. 6):** The final `Refresh_data`/`Create_report` solution must run in Excel using **VBA only** (macros/modules within `treport.xlsm`); the user must not need Python, PowerShell, BAT, or other external runtimes/tools. Auxiliary development and deployment activities may use Python/PowerShell/BAT/other tools (inspection, workbook/pivot metadata, testing/checking, VBA extraction/analysis, test-data prep/validation, diagnostics, one-step build/import automation) provided they do not become runtime dependencies.
- **Access modes (D1):** `Create_report` — data files opened **read-only, never saved**. `Refresh_data` — data files opened **writable (not read-only)** to refresh PQ/RefreshAll and **save**, then closed.
- **Processing order:** `data_files` rows processed in configured order; output sheets follow `data_files` order.
- **Filter field availability and placement (D7, P01):** for every filter field applied (all fields in `data_files.filters` and `reports.articleLevel4Name_clean`, `reports.targetAudience`), availability is determined by presence in the PivotTable's **available fields** (not by whether the field is currently in the Filters area). **Active** (already placed in Filters, Columns, or Rows): keep in current location and apply filtering in place; never move an active field from Columns or Rows into Filters. **Available but inactive** (exists in PivotTable's available fields but not currently placed in Filters, Columns, or Rows): move to Filters area, then apply required filtering and sorting. **Unavailable** (does not exist in PivotTable's available fields): handle as missing required filter field per D12/FR-FLT-7.
- **Filter staging (D8):** for each `data_file`, apply `data_files.filters` once and keep them applied; for each `reports` row apply/reapply that row’s `articleLevel4Name_clean` and `targetAudience` (overriding prior report-row selection for those fields) without moving placed fields and preserving existing layout; one report row’s report-level filters must not leak into another.
- **Deployment automation (P01, FR-DEP):** deployment/import of current VBA modules into `treport.xlsm` must be achievable by a single command/script or equivalent consolidated deployment artifact. Modular source identities (`modTreportConfig/Extract/Files/Filters/Output/Pivot/Refresh/Run/State.bas`, `Sheet1.cls`, `Sheet2.cls`, `ThisWorkbook.cls`) and workbook/document components must be preserved; no blind concatenation, no duplicate modules/procedures, no damage to `Sheet1`/`Sheet2`/`ThisWorkbook`, working-copy only.
- **No invention:** unspecified semantics must not be fabricated; unresolved technical validations are recorded in §13.
- **Determinism:** identical resolved inputs/configuration and data state must yield deterministic resolution, naming, and structure (subject to explicitly stated optional/conditional filter behavior). Repeating build/import must not create duplicates or corrupt the VBA project.

## 7. Confirmed functional requirements

### 7.1 Configuration model (FR-CFG)
- **FR-CFG-1:** Read settings from ListObjects `general`, `reports`, `data_files`, `placeholders` on the `settings` sheet of `treport.xlsm`.
- **FR-CFG-2:** `general` provides `input_path`, `output_path`, `delimeter`. `input_path` and `output_path` are mandatory and non-empty; `delimeter` is mandatory when multi-value splitting is required by config. Missing/empty/invalid required values → fail-fast validation error (D12).
- **FR-CFG-3:** `reports` defines report rows with columns `articleLevel4Name_clean`, `targetAudience`, `name` (one output workbook per row) (D3, D16). Apply `Trim` to configured string values (D14).
- **FR-CFG-4:** `data_files` defines ordered source-processing rows with columns `data_file`, `data_sheet`, `report_sheet`, `filters`, `paste_row`, `paste_col`, `freeze_row`, `freeze_col`, `zoom`, `group_rows`; row order is authoritative for processing and output sheet order (D3, D8). `group_rows` is present in schema but deferred/no-op in current scope (D13). **P04/P05/P07 extensions (implemented):** optional columns `template` (worksheet template name in `ThisWorkbook`), `only_values` (boolean), `insert_rows` (boolean, P05 sample-row model), and `skip_header` (boolean, P07) may be present with backward-compatible defaults when absent/blank; unknown non-empty boolean values fail fast with contextual diagnostics. No `height`/`width` config columns; snapshot size is runtime-derived.
- **FR-CFG-5:** `placeholders` table entries are descriptive/legacy metadata in the workbook; the **authoritative** placeholder model is **`max_<PivotTable field name>`** in `report_sheet` (rev. 7). Any legacy fixed names listed historically do not override the rule that the substituted maximum is resolved from the named PivotTable field (not from `data_files.filters`).
- **FR-CFG-6:** Blank optional fields follow default/no-op where defined (D13). Dropped parameters (`new_file_delimeter`, `keep_col_hidden`) must not be required/processed (D17). Invalid/unsupported/unresolvable expressions or values must not fail silently → fail fast per D12 under the uniform D9 rule (no report-skip exception for missing/no-matchable filter values). P04/P05/P07 optional booleans/`template` follow documented defaults/tokens and fail-fast validation (see `docs/01-vba-reporting/configuration-model.md`).

### 7.2 File resolution and access (FR-FILE)
- **FR-FILE-1:** Resolve each `data_files.data_file` (base name) within the `general.input_path` subtree (`input_path` and all descendant subfolders, recursive search) to `<data_file>.<ext>` considering the fixed allowed extensions **`.xlsx`, `.xlsm`, `.xlsb`**. Extension scan order is not a precedence tie-breaker when multiple candidates exist. Outcome must be deterministic (stable/repeatable).
- **FR-FILE-2:** If no match exists, or if more than one matching candidate exists across the full searched scope and allowed extensions, fail fast with an error listing the configured name, searched path (including subfolders), cause, and candidate paths when ambiguous (D2, D12).
- **FR-FILE-3:** `Create_report` opens data files read-only and never saves them (D1).
- **FR-FILE-4:** `Refresh_data` opens data files writable (not read-only), performs refresh, saves, and closes (D1). Unavailability/lock is a clear fail-fast error (D12).
- **FR-FILE-5:** Ensure `output_path` exists (create if missing) before writing outputs; inability to create/write fails fast (D12).

### 7.3 Refresh operation (FR-REF)
- **FR-REF-1:** For each resolved data file (deterministic order), open writable, refresh Power Query and dependent pivot data so results are persisted, save, and close (D1).
- **FR-REF-2:** Refresh must complete before save/close; asynchronous/background refresh must not leave persisted data stale (technical validation §13, OQ-T2).
- **FR-REF-3:** On refresh failure, fail fast with contextual error (file, stage); do not leave application/workbook state corrupted (D12).

### 7.4 Filter parsing, resolution, and application (FR-FLT)
- **FR-FLT-1 (parse `filters`):** For each `data_files` row, parse `filters` per D5: clauses separated by `|`; each `<field> = <expr>` (trim spaces around `=`, `|`; apply `Trim` consistently to configured strings/tokens; field names may contain spaces). `<expr>` is scalar (literal or `min`/`max`), inclusive range `(start-end)` with numeric/`min`/`max` bounds and `-` operator, or list `(v1<delimeter>v2…)` using `general.delimeter`. Disambiguation: contains `general.delimeter` → list; else contains `-` between two bound tokens → range; else scalar. Empty/invalid/unparseable expression or duplicate/ambiguous clause → fail fast (D12).
- **FR-FLT-2 (resolve `min`/`max`):** Per D10 (rev. 7, user-decided), for each clause in `data_files.filters`, resolve `min`/`max` (and numeric bounds in ranges/lists as applicable) against available numeric values of **the referenced field only** (the field named in that clause), in the relevant pivot context for that `data_files` row. No cross-field dependency-aware year-first scoping is assumed by this rule; any dependency between different fields must be expressed explicitly in configuration if ever required (not defined here). Ranges are inclusive; comparisons/numeric resolution use numeric-convertible values. If a bound/value cannot be resolved → fail fast (D12). Field identity is determined by PivotTable available-field lookup per D7/D9 context (no guessed mappings).
- **FR-FLT-3 (resolve placeholders):** Per D11, for each `max_<field name>` referenced in `report_sheet`, resolve the **maximum numeric value** of that named PivotTable field from available numeric-convertible items of that field in the relevant pivot/data context used for the processed `data_files` row at the time/place this resolution is performed by the implementation (implementation-defined sequencing). Resolution is **independent of `data_files.filters`** clause derivation/representatives (not derived from `data_files.filters`). If not derivable → fail fast (D12).
- **FR-FLT-4 (apply data-file filters):** For each `data_file`, apply resolved `data_files.filters` once to the pivot on `data_sheet` and keep applied for all `reports` rows processed against that `data_file` (D8). `data_files.filters` contains period/data fields as configured/aligned (D4, D10). For each field, determine availability/placement per D7 (P01) before applying selection.
- **FR-FLT-5 (apply report filters):** For each `reports` row, apply `articleLevel4Name_clean` and `targetAudience` using the **uniform rule in D9** (field must exist in PivotTable available fields; if none of specified values matchable → fail fast; if ≥1 match → apply matched subset). Report-level filters are reapplied per report row (override prior report-row selection for those fields) without leaking between report rows and without moving active placed fields (D7, D8). No warn-and-skip of an entire report for “no matching configured values” remains in effect under D9 (replaced by fail-fast).
- **FR-FLT-6 (field availability and placement, P01):** For every filter field applied (all `data_files.filters` fields and `articleLevel4Name_clean`, `targetAudience`), determine usability by presence in the PivotTable's **available fields** (not by whether the field is currently in the Filters area). **Active** (already placed in Filters, Columns, or Rows): leave in its current location and apply filtering in that same location; **never move** an active field from Columns or Rows into Filters and preserve existing PivotTable layout. **Available but inactive** (exists in PivotTable available fields but not currently placed in Filters, Columns, or Rows): move the field to the Filters area, then apply the required filtering and sorting. **Unavailable** (does not exist in PivotTable available fields): treat as missing required filter field per D12/FR-FLT-7.
- **FR-FLT-7 (field identity & outcomes):** Filter field names and literal/value matching follow D5, D9, and D10 (field identity by PivotTable available-field rules; matching after trim/numeric-equivalence as defined). Missing `data_sheet`, missing pivot, a required filter field **unavailable in PivotTable available fields**, or an unresolvable expression/value, or **no matchable specified values** under D9 → fail fast with context (D12). Filter yielding **no data** after applicable selections are applied → fail fast with contextual error (D12).

### 7.5 Report generation and output (FR-RPT)
- **FR-RPT-1:** Create one output workbook per `reports` row named `reports.name` + `.xlsx`. If exists, overwrite on successful run. Lock/overwrite failures → fail fast (D3, D12).
- **FR-RPT-2:** For each `data_files` row in order, create a target sheet in each relevant report workbook named from `report_sheet` after placeholder substitution, in `data_files` order. For idempotency, target sheets are recreated/replaced deterministically (D3, D11).
- **FR-RPT-3:** Copy range = pivot’s presented data after all applicable filters, taken from presented-range basis (`GetPresentedRange`: `TableRange1`, fallback `TableRange2`). Default includes row/column labels and grand totals as shown; exclude pivot object/page-filter area and PQ connections (D15). **P07 (`skip_header=TRUE`):** slice to remove column-header band above data/value body per D15/P07 rules (row labels, data values, subtotals/grand totals in remaining rows preserved as applicable); fail-fast on invalid geometry/offset conditions, `offset==0` no-op.
- **FR-RPT-4:** Paste at `paste_row/paste_col` (blank = default/no-op per D13) as static snapshot. Default transfer: **values + number formats + formats + column widths + row heights** as applicable; `only_values=TRUE` (P04) transfers strict values only and preserves target/template/prepared-row formatting. `insert_rows=TRUE` (P05) uses sample-row preparation and final range `P..P+H-1` after structural changes. Output must not contain pivot objects or PQ connections (D15). Sliced dimensions (P07) must be used consistently for transfer, row prep, final bounds, formatting, and grouping.
- **FR-RPT-5:** Apply formatting per `data_files`: freeze panes (`freeze_row/freeze_col`), zoom, hide gridlines, and row/column sizing/state as required; blanks are no-op/default (D13). `group_rows` is ignored as no-op in current scope (deferred).
- **FR-RPT-6:** `group_rows` color-band grouping is **not implemented** in current scope and must not block processing or acceptance (D13, deferred).
- **FR-RPT-7:** Save each report workbook to `output_path` and release resources; close source files per access-mode rules (D1).

### 7.6 Naming and placeholders (FR-NAME)
- **FR-NAME-1:** Placeholder substitution applies to **`report_sheet` only**. Placeholders use the form **`max_<PivotTable field name>`** written as **`<max_<field name>>`** in templates (e.g. `<max_Year>`, `<max_Week of Year>`). The value is the **maximum numeric value** of that named PivotTable field computed from available numeric-convertible items of that field in the relevant pivot/data context used for the processed `data_files` row at the time/place this resolution is performed by the implementation (implementation-defined sequencing), **independent of `data_files.filters`** clause derivation/representatives (not derived from `data_files.filters`). If referenced but cannot be deterministically derived → **fail fast** (D12). Substituted values are inserted as resolved text **without zero-padding** unless explicitly defined later (not assumed).
- **FR-NAME-2:** Apply `Trim` to configured names/relevant strings before substitution, naming, sanitization, and collision checks (spaces inside names preserved). Sanitize Excel-invalid sheet-name characters, enforce **31-character** limit, and **fail fast** on collision after substitution/sanitization/trimming (D14). Empty/invalid resulting names → fail fast (D12).
