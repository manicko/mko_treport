# P06. Combine Multiple Subreports on One Worksheet and Validate Worksheet Names

Implement two additional features in the report-generation process.

## 1. Combine Multiple Subreports on One Worksheet

### 1.1. Grouping principle

The `data_files` table contains the `report_sheet` parameter, which specifies the name of the final report worksheet.

When multiple `data_files` records within the same output workbook have the same `report_sheet` value, their subreports must be combined into one final worksheet.

Subreports must appear vertically, from top to bottom, in the same order as their records in `data_files`.

### 1.2. Stage 1 — Prepare individual subreports

Preserve the existing subreport preparation process as much as possible.

Each subreport must first be fully generated on a separate worksheet, regardless of whether a template is used.

Worksheet naming:

- The first subreport uses the base name specified in `report_sheet`.
- Subsequent subreports use temporary names with sequential numeric suffixes: `<report_sheet>1`, `<report_sheet>2`, etc.
- If a generated name already exists in the output workbook or conflicts with another planned worksheet name, stop with an error. Tell the user which name conflicts and ask them to change the conflicting name.
- Never automatically delete, overwrite, or rename existing worksheets.

For each output workbook, maintain a grouping structure containing:
- The base `report_sheet` name.
- An ordered list of temporary worksheets belonging to that report.
- The `gap_rows` value associated with each temporary worksheet.

Keep this information isolated per output workbook. Do not mix subreports belonging to different output workbooks.

### 1.3. Stage 2 — Combine prepared subreports

After all individual subreports have been prepared, perform a second pass through the output workbooks.

For each report group:

1. Locate the base worksheet. It already contains the first subreport.
2. Determine its last used row:

   `lastRow = UsedRange.Row + UsedRange.Rows.Count - 1`

3. Set the next available row:

   `nextRow = lastRow + 1`

4. Process temporary worksheets sequentially, in their original `data_files` order.

For each temporary worksheet:

- Get its `UsedRange`.
- Validate its size using the per-worksheet `report_rows_limit_general` rule described below.
- Calculate the destination row:

  `destinationRow = nextRow + gap_rows`

- Copy the source `UsedRange` to the base worksheet, starting at `destinationRow`.
- Preserve the source range's starting column. Do not apply `paste_row` or `paste_col` again, because these offsets have already been applied during initial subreport preparation.
- Set the next insertion position:

  `nextRow = destinationRow + sourceUsedRange.Rows.Count`

`gap_rows` specifies the number of empty rows before the next subreport. If it is blank or not specified, use 0.

### 1.4. Data and formatting to preserve

When combining worksheets, transfer:

- Cell values (not formulas).
- Cell formatting, including number formats.
- Row grouping and outline levels.
- Hidden row states.
- Row heights.

Do not transfer:

- Column widths.
- Hidden column states.
- Zoom.
- FreezePanes.
- SplitRow and SplitColumn.

The base worksheet must retain its existing column layout and display settings.

Grouping and hidden rows must be restored on the final worksheet using the new row positions of each subreport.

### 1.5. Row limits and Excel worksheet limits

There are two separate validation rules. They must not be confused.

**A. `report_rows_limit_general` — individual subreport limit**

Apply this limit independently to every prepared subreport worksheet, including the base worksheet containing the first subreport.

Before combining, validate each worksheet's own `UsedRange.Rows.Count` against `report_rows_limit_general`.

If an individual worksheet exceeds this limit, stop with an error identifying:
- The worksheet name.
- The associated `report_sheet`.
- The actual row count.
- The configured `report_rows_limit_general` value.

This is an individual worksheet safety check, including protection against unexpectedly large or incorrectly determined `UsedRange` values.

**Do not apply `report_rows_limit_general` to the combined report or the sum of all subreports.**

**B. Excel worksheet hard limits — final combined worksheet**

Independently validate the projected dimensions of the final combined worksheet before each paste operation.

Excel worksheet limits are:
- Maximum rows: 1,048,576.
- Maximum columns: 16,384.

Calculate the destination range boundaries using the actual source `UsedRange` dimensions and destination coordinates.

If the combined worksheet would exceed either Excel limit, stop with a clear error containing:
- The final `report_sheet` name.
- The projected row or column boundary.
- The applicable Excel limit.

Do not attempt the paste operation when it would exceed Excel worksheet limits.

### 1.6. Cleanup

After all subreports belonging to a group have been successfully combined, delete their temporary worksheets.

The final output workbook must contain the base worksheets with the combined reports, not the temporary subreport worksheets.

Do not delete temporary worksheets until their content has been successfully transferred.

## 2. Worksheet Name Length Validation

Excel worksheet names cannot exceed 31 characters.

Validate all worksheet names generated during report preparation, including temporary names with numeric suffixes.

Rules:

- Validate the original `report_sheet` name.
- Validate every generated temporary worksheet name.
- If a name exceeds the limit, stop before creating the affected worksheets.
- Display the original report name without its generated numeric suffix.
- Calculate the maximum allowed base-name length by subtracting the suffix length from 31.

Example:

- Maximum Excel worksheet name length: 31 characters.
- Generated suffix: `12` (2 characters).
- Maximum allowed base name: 29 characters.

The error message must show:
- The original report name without the suffix.
- The maximum permitted length of the base name.
- A recommendation to shorten the name.

Example error:

`Report sheet name '<original_name>' is too long. The maximum allowed length for this base name is 29 characters because the generated suffix '12' requires 2 additional characters. Please shorten the report name.`

## 3. General Implementation Requirements

- Preserve the existing subreport preparation mechanism.
- Keep the initial report generation process independent from the subsequent combining process.
- Perform grouping and combining separately for each output workbook.
- Preserve the original `data_files` processing order.
- Do not apply `paste_row` or `paste_col` offsets a second time.
- Do not transfer worksheet-level display settings from temporary worksheets.
- Do not delete or overwrite existing worksheets when name conflicts occur.
- Keep `report_rows_limit_general` as an individual subreport limit.
- Validate the final combined worksheet against Excel's actual worksheet row and column limits.
- Avoid unnecessary changes to existing report-generation logic.

**Expected result:**

Multiple subreports with the same `report_sheet` value are initially prepared on separate worksheets and then combined vertically into one final worksheet.

The final worksheet preserves all required cell content, formatting, row heights, row grouping, and hidden row states.

Temporary worksheets are removed after successful combining, and both individual subreport limits and final Excel worksheet limits are enforced.
