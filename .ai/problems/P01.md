## 1. Pivot field availability and filter placement

We need to change the current logic for determining whether a pivot field can be used.

**The key principle: field availability must be determined by its presence in the PivotTable, not by whether it is already placed in the Filters area.**

The required behavior is:

1. When a field is not found in the Filters, Columns, or Rows areas, consider it inactive (not currently placed in the PivotTable layout).
2. Check whether the field actually exists in the PivotTable's available fields.
3. If the field exists in the PivotTable, it can still be used:
   - Move it to the Filters area.
   - Apply the required filtering and sorting.
4. If the field is already active in the PivotTable, meaning it is used in the Filters, Columns, or Rows area:
   - Leave it in its current location.
   - Apply filtering in that same location.
   - Do not move it to the Filters area.

**Important constraint:** Do not move an active field from Columns or Rows into Filters. Its existing PivotTable layout must be preserved.

The distinction is:

- **Available but inactive:** the field exists in the PivotTable but is not currently placed in Filters, Columns, or Rows. Move it to Filters before applying the filter.
- **Active:** the field is already placed in Filters, Columns, or Rows. Keep it there and apply the filter in place.
- **Unavailable:** the field does not exist in the PivotTable at all. Handle this according to the existing missing-field/error requirements.

Currently, the implementation appears to depend too heavily on whether a field is already present in the Filters area. This is the limitation we need to eliminate.

The implementation must recognize that a field can be available in the PivotTable and usable even when it is not currently located in the Filters area.

Please update the relevant functional requirements, business rules, implementation guidance, and acceptance tests accordingly.
