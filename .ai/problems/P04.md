# Промпт 4. Расширение механизма вставки данных и поддержка листов-шаблонов Excel

Необходимо доработать существующий механизм формирования отчетов, добавив две независимые функциональные возможности:

1. Расширение механизма вставки данных с помощью параметров `only_values` и `insert_rows`.
2. Возможность создания итогового листа на основе шаблона с помощью параметра `template`.

**Важно: это две независимые функциональные возможности. Параметры `only_values` и `insert_rows` должны работать независимо от того, создается отчет на обычном листе или на основе шаблона.**

## 1. Общая архитектура

Файл `treport.xlsm` является файлом макроса и настроек. В нем находится таблица настроек `data_files`.

Каждая запись в таблице `data_files` представляет собой отдельный небольшой отчет (`subreport`) — диапазон ячеек, который копируется из исходных данных и вставляется в итоговый отчет.

Сейчас реализован следующий механизм:
1. Создается новый лист в файле отчета.
2. Листу присваивается имя из колонки `data_sheet` таблицы `data_files`.
3. На созданный лист вставляются данные соответствующего subreport.

Необходимо сохранить существующий механизм и дополнить его новыми возможностями.

## 2. Параметры `data_files`

Для данной задачи используются следующие параметры:

| Параметр | Назначение |
|---|---|
| `data_sheet` | Имя итогового листа в файле отчета |
| `template` | Имя листа-шаблона в книге макроса `treport.xlsm` |
| `only_values` | Определяет способ копирования данных: только значения или значения вместе с форматированием |
| `paste_row` | Номер строки, в которую вставляются данные |
| `paste_col` | Номер столбца, в который вставляются данные |
| `insert_rows` | Определяет, нужно ли предварительно добавлять строки перед вставкой данных |

Высота и ширина вставляемого диапазона определяются существующими параметрами subreport:
- `height` — высота диапазона в строках;
- `width` — ширина диапазона в столбцах.

## 3. Функциональность №1. Расширение механизма вставки данных

Данная функциональность должна работать **для всех subreport независимо от способа создания целевого листа**.

То есть параметры `only_values` и `insert_rows` применяются:
- при вставке данных на обычный вновь созданный лист;
- при вставке данных на лист, скопированный из шаблона.

### 3.1. Параметр `only_values`

Определяет, что именно переносится из исходного диапазона в целевой диапазон.

Если `only_values = TRUE` или `only_values = 1`:

- Копировать только значения ячеек.
- Не переносить форматирование из исходного диапазона.
- Не заменять форматирование целевого листа форматированием исходных ячеек.

Если `only_values = FALSE` или `only_values = 0`:

- Выполнять стандартное копирование значений и форматирования ячеек.
- Использовать существующий механизм копирования и вставки, если он уже реализован.

Параметр должен работать одинаково при вставке как на обычный лист, так и на лист-шаблон.

### 3.2. Параметр `insert_rows`

Определяет, требуется ли предварительно добавлять строки на целевом листе перед вставкой данных.

**Важно: речь идет о целевом листе, а не исключительно о листе-шаблоне.**

Параметр должен работать независимо от того, каким способом был создан целевой лист.

#### Если `insert_rows = FALSE` или `0`

Использовать обычный механизм вставки:

1. Определить позицию вставки по `paste_row` и `paste_col`.
2. Выполнить вставку данных в указанную ячейку.
3. Не добавлять и не удалять строки целевого листа.

#### Если `insert_rows = TRUE` или `1`

Выполнить следующую последовательность:

**Шаг 1. Определить параметры вставки**

- `paste_row` — строка начала вставки;
- `paste_col` — столбец начала вставки;
- `height` — высота вставляемого диапазона;
- `width` — ширина вставляемого диапазона.

**Шаг 2. Добавить строки**

Относительно позиции вставки `paste_row` предварительно добавить строки листа в количестве, равном `height`.

Добавление строк должно выполняться средствами Excel таким образом, чтобы новые строки могли наследовать форматирование окружающих строк целевого листа.

**Шаг 3. Выполнить вставку данных**

Вставить данные в подготовленный диапазон с учетом параметра `only_values`:

- `only_values = TRUE` — вставлять только значения;
- `only_values = FALSE` — вставлять значения и форматирование.

**Шаг 4. Удалить вспомогательные строки**

После вставки необходимо удалить:
- одну строку непосредственно над вставленным диапазоном;
- одну строку непосредственно под вставленным диапазоном.

Это необходимо для удаления вспомогательных строк и сохранения предусмотренного оформления целевого листа.

Удаление строк должно учитывать изменение координат диапазона после добавления и удаления строк. Итоговый диапазон данных должен оставаться в корректном положении.

**Архитектурное требование:**

Удаление дополнительных строк необходимо реализовать отдельной функцией.

Не размещать непосредственно в основном алгоритме вставки жестко заданную логику удаления строк.

В дальнейшем удаление дополнительных строк может стать отключаемой операцией. Поэтому функция должна быть независимой и предусматривать возможность ее отдельного вызова или пропуска.

Данная функция должна применяться одинаково для обычного целевого листа и для листа, созданного на основе шаблона.

## 4. Функциональность №2. Создание листа на основе шаблона

Данная функциональность отвечает исключительно за подготовку целевого листа, на который будут вставляться данные.

Если в таблице `data_files` параметр `template` заполнен, необходимо использовать указанный лист в качестве шаблона.

### 4.1. Если `template` не заполнен

Использовать существующий механизм:

1. Создать новый лист в файле отчета.
2. Присвоить ему имя из `data_sheet`.
3. Подготовить лист для вставки данных.

Никаких изменений в существующем механизме создания обычного листа вносить не нужно.

### 4.2. Если `template` заполнен

Выполнить следующую последовательность:

1. Найти лист с именем, указанным в `template`, в книге макроса `treport.xlsm`.
2. Скопировать этот лист в книгу итогового отчета.
3. Присвоить скопированному листу имя из `data_sheet`.
4. Использовать полученный лист как целевой лист для дальнейшей вставки данных.

Необходимо копировать весь лист, сохраняя:
- форматирование ячеек;
- ширину столбцов и высоту строк;
- объединения ячеек;
- формулы;
- структуру листа и другие элементы оформления шаблона.

Исходный шаблон в `treport.xlsm` не должен изменяться.

Все дальнейшие операции выполняются только с копией шаблона в итоговой книге.

Если указанный шаблон не найден, необходимо вывести понятную ошибку с указанием имени шаблона и соответствующего `data_sheet`.

## 5. Общий алгоритм формирования subreport

Для каждой записи таблицы `data_files` необходимо выполнять следующий алгоритм.

**Этап 1. Подготовка целевого листа**

1. Прочитать значение `template`.
2. Если `template` пустой — создать обычный новый лист, используя существующий механизм.
3. Если `template` заполнен — скопировать указанный лист из `treport.xlsm` в итоговую книгу и присвоить ему имя `data_sheet`.

После выполнения этого этапа у нас в любом случае должен быть готов целевой лист для вставки данных.

**Этап 2. Подготовка диапазона для вставки**

1. Прочитать `paste_row`, `paste_col`, `height`, `width`.
2. Прочитать значение `insert_rows`.
3. Если `insert_rows = TRUE` — предварительно добавить строки в целевой лист в количестве `height`.
4. Если `insert_rows = FALSE` — пропустить добавление строк.

**Этап 3. Вставка данных**

1. Прочитать значение `only_values`.
2. Выполнить вставку данных в целевой лист:
   - только значения, если `only_values = TRUE`;
   - значения и форматирование, если `only_values = FALSE`.

**Этап 4. Завершение вставки**

Если `insert_rows = TRUE`:
1. Вызвать отдельную функцию удаления вспомогательных строк.
2. Удалить одну строку сверху и одну строку снизу от вставленного диапазона.

Если `insert_rows = FALSE`, дополнительное удаление строк не выполнять.

**Этап 5. Переход к следующему subreport**

Перейти к следующей записи `data_files` и повторить алгоритм.

## 6. Сочетание параметров

Все параметры должны работать независимо друг от друга.

Возможны следующие сочетания:

| `template` | `only_values` | `insert_rows` | Результат |
|---|---|---|---|
| Пустой | FALSE | FALSE | Обычный лист, стандартная вставка значений и форматирования |
| Пустой | TRUE | FALSE | Обычный лист, вставка только значений |
| Пустой | FALSE | TRUE | Обычный лист, предварительное добавление строк, стандартная вставка, удаление вспомогательных строк |
| Пустой | TRUE | TRUE | Обычный лист, предварительное добавление строк, вставка только значений, удаление вспомогательных строк |
| Имя шаблона | FALSE | FALSE | Копия шаблона, стандартная вставка значений и форматирования |
| Имя шаблона | TRUE | FALSE | Копия шаблона, вставка только значений с сохранением оформления шаблона |
| Имя шаблона | FALSE | TRUE | Копия шаблона, предварительное добавление строк, стандартная вставка, удаление вспомогательных строк |
| Имя шаблона | TRUE | TRUE | Копия шаблона, предварительное добавление строк, вставка только значений, удаление вспомогательных строк |

## 7. Требования к архитектуре реализации

Важно разделить логику на независимые функции:

1. **Создание целевого листа**
   - создание обычного листа;
   - создание листа на основе шаблона.

2. **Подготовка строк**
   - добавление строк перед вставкой, если `insert_rows = TRUE`.

3. **Вставка данных**
   - вставка только значений;
   - вставка значений и форматирования.

4. **Удаление вспомогательных строк**
   - отдельная функция удаления строки сверху и снизу от вставленного диапазона.

Основной алгоритм формирования отчета должен только определять необходимые параметры и последовательно вызывать соответствующие функции.

Не создавать две разные реализации вставки данных — одну для обычного листа и другую для шаблона. Использовать единый механизм вставки, который работает с переданным ему целевым листом.

### Обратная совместимость

- Не нарушать существующий механизм формирования отчетов.
- Если `template` не заполнен, создание листа должно работать по старому принципу.
- Если новые параметры не заданы, использовать поведение существующего механизма: обычная вставка без добавления строк.
- Новые параметры должны быть необязательными для существующих записей `data_files`.
- Некорректные параметры необходимо обрабатывать без аварийного завершения всего формирования отчетов, если это допускает существующая архитектура.

## 8. Ожидаемый результат

После доработки система должна иметь единый механизм вставки данных с возможностью управления способом вставки и предварительной подготовкой строк.

При этом создание целевого листа и способ вставки данных должны быть независимыми друг от друга.

`template` отвечает только за способ создания целевого листа.

`only_values` отвечает за способ копирования данных.

`insert_rows` отвечает за предварительное добавление строк и последующее удаление вспомогательных строк.

Все три параметра могут использоваться в любых допустимых сочетаниях.
