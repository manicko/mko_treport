# P09 — `insert_rows` (template): sample row `P` inserted `H-2` times, snapshot pasted at `P-1`

- **Status:** Ready for implementation planning (targeted rework; spec/contract alignment required)
- **Date:** 2026-11-17
- **Source:** User clarification (2026-11-17), superseding earlier deletion-based ideas:
  - Initial report: when inserting into template with `insert_rows=TRUE`, upper/lower rows in the inserted area are not deleted.
  - Clarification 1: need to delete template rows **above and below** the inserted range (not shrink snapshot).
  - **Final direction (this task):** "можно без удаления. Можем в коде сделать, чтобы sample-строка P вставлялась H-2 раза. А копирование должно осуществляться в ячейку P-1."

## 1. Objective

Adjust `insert_rows=TRUE` insertion/preparation for template use so that the template rows immediately above and below the originally targeted area are covered without deleting rows and without shrinking the copied/inserted snapshot range.

## 2. Required behavior

Let `P = configured paste_row`, `pc = paste_col`, `H = snapshot.Rows.Count`, `W = snapshot.Columns.Count` (after existing `skip_header` slicing, if applicable).

- **No row deletion.** Do not delete template rows above/below the inserted range.
- **No snapshot shrink.** Insert full snapshot `H x W`.
- **Sample-row preparation:** use entire target-sheet row `P` as the sample/formatting row and insert it **`H-2` times** (instead of current `H-1`).
- **Snapshot anchor:** perform snapshot copy/paste to top-left cell **`(P-1, pc)`** (one row above configured `P`), not `(P, pc)`.
- **Formatting/values transfer:** preserve current `only_values` semantics (`TRUE` = values only preserving prepared/target formatting; `FALSE` = existing snapshot transfer including values/number formats, formats, column widths, row heights).
- **Final range:** returned range and all downstream operations (sheet formatting, outline grouping) must use the **actual post-insert snapshot bounds**.

## 3. Current implementation (root cause / baseline)

**`mko_treport/src/vbs/export/modTreportExtract.bas` (`CopyPivotSnapshot`, P05/P07):**
- `H/W` from presented range (`:43-80`); `pr=pasteRow`, `pc=pasteCol`, clamped to `>=1` (`:31-34`).
- If `insertRows And H > 1`: copies entire row `P` and inserts **`H-1`** copies starting at `P` (`:82-89`), prepared space `P..P+H-1`.
- Pastes snapshot at **`(P, pc)`** (`:91-92`), returns **`P..P+H-1`** (`:94`).
- No deletions; P05/GA-P05-7 removed helper-row deletion (`:17-19,141`).

**`mko_treport/src/vbs/export/modTreportRun.bas:200-212`:** normalizes `pr/pc >= 1`, calls `CopyPivotSnapshot(..., pr, pc, ..., onlyValues, insertRows, skipHeader)`, passes returned range to `ApplySheetFormatting` / `ApplyOutlineGrouping`.

**Docs/specs (currently aligned with P05, must be reconciled):** `docs/01-vba-reporting/configuration-model.md:57,65`, `docs/01-vba-reporting/pipeline-and-dataflow.md:60,88`, `.ai/problems/005_p05_insert_rows_template_row_spec.md` (accepted; defines `H-1` inserts at `P`, snapshot at `P`, final `P..P+H-1`, no deletions).

## 5. Edge cases / decisions to confirm

- **OP-1 (scope):** apply only when `insert_rows=TRUE` **and template is set** (assumed from context) or to all `insert_rows=TRUE` targets?
- **OP-2 (`H` values):** `H-2` behavior must be deterministic:
  - `H >= 3`: insert `H-2` sample rows.
  - `H == 2`: insert `0` sample rows (paste `2 x W` at `P-1`) — assumed valid unless stated otherwise.
  - `H == 1`: `H-2 < 0` — **decision needed**: fail-fast or treat as `0` inserts with paste at `P-1`? (P05 currently allows `H=1` with 0 inserts at `P`).
- **OP-3 (`P == 1`):** cannot paste at `P-1`; assumed **fail-fast** with diagnostic (preferred) vs alternative anchor rule — confirm.
- **OP-4 (contract):** `paste_row` remains configured value; actual snapshot top becomes `P-1` and returned range/grouping follow actual placement. Sample row remains entire row `P`.
- **Excel behavior:** row inserts starting at `P` shift row `P`/below down; combined with writing at `P-1`, final coordinates and sample-format coverage of `P-1`/bottom boundary must be verified on working copies (L3), including merges/formulas/CF in templates.

## 6. Acceptance criteria

- For in-scope case: sample row `P` inserted `H-2` times (per confirmed rule), snapshot written at `(P-1, pc)` with full `H x W`, no deletions, no snapshot shrink.
- Returned final range matches actual snapshot bounds; `ApplySheetFormatting` and `ApplyOutlineGrouping` operate correctly on it.
- `only_values=TRUE/FALSE` and `skip_header` behave correctly with new anchor/count.
- Out-of-scope cases unchanged (`insert_rows=FALSE`; non-template if template-only).
- Invalid anchor/`H` cases handled per confirmed rule with actionable fail-fast diagnostics.
